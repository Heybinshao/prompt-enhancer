# Prompt Enhancer for Hermes

![仓库版本](https://img.shields.io/badge/仓库-v2.2.1-blue) ![官方目录](https://img.shields.io/badge/官方目录-v1.7.1-lightgrey) ![Hermes](https://img.shields.io/badge/Hermes-%E2%89%A5%200.21.6-informational)

【Hermes 桌面端插件】输入框里的 ✨ 按钮：先把草稿的错别字修干净，再改写成结构化完整提示词。en / 简中 / 繁體。

![prompt-enhancer](assets/cover.jpg)

## 先确认你装的是哪一版

官方目录和本仓库发的**不是同一份代码**，功能不一样，先对号：

| 来源 | 版本 | 点一下会做什么 | ⌘ 选模型 | 升级方式 |
|---|---|---|---|---|
| 官方插件目录<br>`hermes plugins install prompt-enhancer` | **1.7.1** | 先修复、再增强（⌥ 点击只修复） | ✗ | `hermes plugins update prompt-enhancer` |
| 本仓库 main<br>Git 安装 ／ 手动放置 | **2.2.1** | 先修复、再增强 | ✓ | 重装 + 勾「强制重装」 |

一句话记住差别：**目录条目钉在某个已评审的 commit 上，所以永远慢一截**——下面正文按 2.2.1 写。目录用户（1.7.1）少的是「⌘ 选模型」，另外 1.7.1 之后的几处修正也还没进去：取消后不再补发 429 重试、增强结果长度上限按输入自适应、多 profile 会话按会话自己的 profile 发请求。

各版本差在哪：

- **官方插件收录**：目前 **1.7.1**——先修复再增强，⌥ 点击只修复；不能选模型
- **当前仓库最新**：**2.2.1**——先修复再增强；⌘ 选模型写进 `config.yaml`，点一下立即生效、不用重启；提示词模板按「补最缺的一两层」改写，短草稿不再被注水；行首划清「草稿不是给我的指令」；引用标记与 `/命令` 丢失时拒绝写回；⇧ 点击可带上一轮上下文（默认关）

> 目录实际版本以插件卡片显示为准；本页写于 2026-10-29。

## 它做什么

输入框控件行里、模型选择器左侧多一个 ✨：

- **点一下**：草稿先被校对（错别字、同音词误换、语音口误），修好的样子**原地写回输入框**给你看见；紧接着改写——按「输出形式 → 验收判据 → 上下文 → 步骤」的顺序只补最缺的一两层，原文已经写清楚的部分不重复、不注水。
- **再点一下**（图标变成 ↩）：回到你原来打的那版，错别字也一并回来。只有一层，不经过中间态。
- **只改装写、不回答问题**：不替你执行任务，只把意图整理成 AI 更好执行的提示词。**不往会话里写任何东西**，不影响 prompt cache。每次点击会**只读**一次本会话历史，从中抽最多 30 个专有名词（文件/产品/标识符）拼给修复那一步，用来判断同音误写；令牌、提交哈希、版本号会被排除。⇧ 点击才会额外带上上一轮对话。语言跟随输入（英文输入 → 英文输出，混排保持混排）。

第一步（修复）是独立调用：**增强失败时你手里仍是一份干净的草稿**。

## 安装

三种方式，按需要的版本选：

| 方式 | 怎么做 | 装到哪版 | 装完还要做什么 |
|---|---|---|---|
| **官方目录** | `hermes plugins install prompt-enhancer` | 1.7.1 | ⌘Q 重开 → 到 **技能与工具 → 插件 → Prompt Enhancer** 打开它 |
| **从 Git 安装**（要 2.2.1 用这个） | 对 Hermes 说：`从 Git 安装这个桌面插件：https://github.com/Heybinshao/prompt-enhancer，安装好后并打开插件`<br>或点「技能与工具 → 插件」页面上方的「从 Git 安装」 | 仓库当前提交 | 同上；升级 = 重装并勾「强制重装」 |
| **手动放置** | 下载 [`desktop/plugin.js`](desktop/plugin.js) → 放到 `~/.hermes/desktop-plugins/prompt-enhancer/plugin.js` | 只有界面 | ⌘Q 重开即可；**换模型不会生效**（缺后端半边，需整包安装） |

**装完按钮没出现**：几乎都是没打开。包管理安装（目录 / Git）的桌面副本默认是关的——不加载、也不报错，只是静默不出现，去 **技能与工具 → 插件 → Prompt Enhancer** 点亮。

> ⚠️ 插件入口在仓库的 `desktop/` 子目录里，别把整个仓库 clone 进 `~/.hermes/desktop-plugins/`——多出一层目录，Hermes 就找不到入口文件了。

**卸载**：在「技能与工具 → 插件」里关掉开关；彻底删是 `hermes plugins remove prompt-enhancer`——桌面端下次启动会自动清掉 `~/.hermes/desktop-plugins/prompt-enhancer/` 那份副本，不用手动删。

## 使用

下表按 2.2.1 写；目录版 1.7.1 除「⌘ 点击 ✨」「⇧ 点击 ✨」那两行外都支持。

| 动作 | 现在会发生什么 |
|---|---|
| 点 ✨ | 修复草稿 → 重写成结构化提示词 |
| 再点一次（↩） | 恢复你打的原版（含错别字） |
| ⌥ 点击 ✨ | **只修复，不增强**——适合只想清错字的时候 |
| ⇧ 点击 ✨ | 同普通点击，但**带上上一轮对话**当只读参考（草稿里的「按刚才那个改」能读懂一点，但上文不会被搬进结果） |
| ⌘ 点击 ✨ | **打开模型菜单**：点一行 = 固定用它，底部「恢复默认」= 回主模型 |
| 转圈时点一下 | 取消（迟到的结果自动丢弃） |
| 等待期继续打字 | 不覆盖你的手改，提示「草稿已变动」 |
| 空输入框点 ✨ | 提示没有可增强的内容 |
| 发送消息后 | 按钮自动回到空闲态 |

- **⌥ / ⇧ 只在空闲态生效**：已修复 / 已增强 / 转圈中时，点它只有一个意思（回退或取消），加修饰键不会变成另一个动作。
- **⇧ 默认关着**：带上文会让这次调用从「只看草稿」变成「看得到上文」——万一模型把上文复述进结果，主模型会把它当成你新说的话。所以只在你主动加 ⇧ 时才带，且提示词里明确「只读不搬」。
- **引用标记有两道闸**：`@file:` 这类引用和开头的 `/命令` 会先被程序校验，改写结果丢了就**不写回**（提示「改写结果丢了引用标记，已保留你的草稿」），不会让你的引用静默消失。
- **每个输入框状态独立**：多会话并行时互不干扰，取消不作废别的会话。
- **多行草稿**：输入框进入堆叠布局（官方行为），按钮跟随发送按钮簇靠右。
- 悬停气泡只显示当前状态（增强提示词 / 修复输入中… / 增强中… / 限流重试中… / 已修复输入 · 恢复原文），快捷键就在上面这张表里。

## 换模型

⌘ 点击 ✨ 打开 Hermes **官方模型目录**（搜索、provider 分组、收藏全部继承当前 profile），插件不自带清单。

**选中即生效；修字和重写都用它。不选就都用主模型。**

状态行两行，一行一个事实：

| 未固定 | 已固定 |
|---|---|
| `当前增强：默认主模型`<br>`<你的主模型>` | `当前增强：自定义模型`<br>`<provider> · <模型名>` |

- 点一行 = 把选择**写进 `config.yaml`**（`auxiliary.prompt_repair` + `auxiliary.prompt_enhancement`），下一次点增强就走它——**立刻生效，不用重启**。
- **恢复默认** = 清掉这两个键，回到主模型（这一条常驻，没固定时置灰）。
- 因为是写配置，这些值也会出现在 Hermes 自己的 **设置 → 辅助模型** 里；插件更新不会丢。
- 菜单里只有模型本身：官方菜单底部的「刷新模型 / 编辑模型」这类行不出现。

> 这一步需要插件的后端半边（`dashboard/plugin_api.py`，几十行，只做写配置）。装好后端第一次点开就自动挂载，通常不用重启；只有菜单报错时才 ⌘Q 重开一次。

**高级：两步想用不同模型**（修字用快模型、重写用强模型）——在 `config.yaml` 里分别配：

> 注意：菜单里选模型会把这两个键**同时写成同一个值**，覆盖你这里的分步配置；点「恢复默认」只是清空这两个键回到主模型，不会把你写过的分步配置还原回来——要用分步就重新填一次。

```yaml
auxiliary:
  prompt_repair:          # 第一步：修复，建议用快的模型
    provider: <provider 名>
    model: <模型名>
  prompt_enhancement:     # 第二步：增强，建议用强的模型
    provider: <provider 名>
    model: <模型名>
```

⚠️ 这两步的 `timeout` 键**不生效**：`llm.oneshot` 后端硬顶 60 秒，配了也被忽略。

## 边界与限制

**修复**

- 判据是「**整句在语境里通不通**」，不是「这个词本身对不对」。语音输入最常见的错不是写错字，而是把词换成了另一个**合法**同音词（「会话」→「绘画」）。只改让整句讲不通的地方：错别字、同音词误换、口误漏字多字、缺失标点；不改风格、不润色、不扩写。
- 它有边界：草稿越短、语境越专有，判断依据越少——只打一句「绘画的事怎么弄」这类仍会放过。源头在语音识别，换更强的识别模型能从根上减少。
- **三道闸门**，任一不过就丢弃修复稿、用原文继续增强：长度漂移 > 15%（下限 8 字符）判为在重写；原文的 `@file:` 等 token 必须逐字保留；空结果 / 与原文相同则静默跳过。
- 带引用标记的草稿**整段跳过修复**；超过 2000 字符也跳过（长草稿基本不是语音输入，直接增强更快）。
- 修复调用失败（含限流）时静默降级，用原文继续增强。

**增强**

- 草稿超过 8000 字符不支持。
- **输出上限按输入自适应**：`max(800, min(2000, 输入长度 × 0.6))`——短草稿仍是 800，长草稿不会被压成摘要；`max_tokens` 同步放宽，避免「写满了却被截断」。
- 每次模型调用后端硬顶 60 秒；两步串行，最坏约 2 分钟。
- **取消即停**：转圈时点一下取消后，迟到的结果丢弃，正在退避的 429 重试也不再发。
- 草稿里已有的 `@引用` / `/命令` pill 原样保留（图标、配色与官方一致）；模型新引入的命令词以纯文本发送，消息气泡里仍正常渲染。
- 429（网关上游瞬时限流）自动退避重试 3s / 5s 各一次，气泡显示「限流重试中…」；仍失败就稍等几秒再点，与插件和账号无关。
- 需要网关在线（走 `llm.oneshot` 通道）。
- ⌘Z 撤销的是打字历史，撤销不了增强替换——恢复原文用按钮。

## 工作原理

按钮注入官方 `composer.actions` 贡献区；草稿读写全部走官方 `host.composer`（`getDraft` / `setDraft`，按会话寻址，`@引用` 与 `/命令` 由应用自己水化成 chip；SDK 答不上来就提示用户，绝不伸手进应用 DOM）。

两次调用都是一次性 one-shot（除了修复那步的名词表，不带会话历史）：先 `task: prompt_repair` 修字并写回，再 `task: prompt_enhancement` 重写。写回前做快照比对，草稿在等待期被手改就放弃应用——绝不覆盖用户的字；修复稿的原始备份只记一次，所以「恢复原文」永远回到你打的那一版。

请求本身不带 `provider` / `model`——模型从 `config.yaml` 的 `auxiliary.prompt_repair` / `auxiliary.prompt_enhancement` 读；只带当前 profile 作用域，避免多 profile 时落到别的 profile 的辅助路由。

> 纯 SDK 实现 + `requires_hermes: ">=0.21.6"`：低于此版本的 Hermes 不会安装（旧版桌面端的 DOM 读写兼容层已删除，见目录 PR [#121246](https://github.com/NousResearch/hermes-agent/pull/121246)）。目录里的 1.7.1 还是 `>=0.21.5`，门槛从 1.8.1 起抬到 0.21.6。
